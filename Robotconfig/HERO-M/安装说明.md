这张表说明控制板和主要部件固定在哪个机械坐标上。坐标总口径见 [坐标系和安装基准](../../manual/算法协议与坐标.md)。

## 当前结论

| 项目 | 当前定义 |
| --- | --- |
| 控制板 | `DmMc02H7` |
| 控制板固定部件 | 单云台本体 |
| INS 姿态主要代表 | 云台姿态 |
| 底盘坐标 | `+X` 车体正前，`+Y` 车体左侧，`+Z` 向上 |
| 云台坐标 | `+X` 按云台 yaw 的水平朝向，`+Y` 为其左侧 |
| 算法 `q[4]` | 板端姿态参考，按当前安装可理解为云台姿态参考 |
| 算法 `frame=2` | 来自板端姿态估计；没有外部定位时，场地基准仍受上电方向和 yaw 漂移影响 |

## 机械层级

```text
场地
  -> 底盘车体
      -> 云台 yaw
          -> pitch / 相机 / 枪管（控制板固定在云台本体上）
```

HERO-M 没有大 yaw / 小 yaw 两级拆分。算法如果按相机或云台朝向移动，优先使用 `frame=0`。

## 俯仰补偿表

`PitchCaliBuiltin.c` 保留 HERO-M 的 33 点默认补偿表。它由历史记录中的 10 个测点通过保形三次 Hermite 插值离线展开，运行时仍查表插值，不在线拟合。开启俯仰补偿时，`PitchCaliBootLoad()` 先加载内置表，再尝试 SD 卡文件；SD 文件通过校验后会覆盖内置表，读取失败时保留内置表。旧笔记的“内置表始终优先”说法已不符合当前代码。表被编入固件不代表它已经适配当前机械状态，更换电机、减速结构、负载或零位后应重新测量。

原始记录未附测量日期和完整硬件条件，以下数值只保留来源，不能视为当前实车验收数据。角度单位为 rad，其余数值是旧控制接口的电流指令刻度，不是安培：
