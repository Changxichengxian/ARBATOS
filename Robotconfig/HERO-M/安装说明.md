## 机械层级

```text
场地
  -> 底盘车体
      -> 云台 yaw
          -> pitch / 相机 / 枪管（控制板固定在云台本体上）
```

HERO-M 没有大 yaw / 小 yaw 两级拆分。算法如果按相机或云台朝向移动，优先使用 `frame=0`。

## CAN 功率计

功率计接 CAN1，配置在 `ConfigHardware.inc` 的 `.powerMeter`：默认启用、标准 ID `0x212`、新鲜度阈值 20 ms。当前车端 CAN1 为 1 Mbit/s，设备必须设置相同总线速率；1000 Hz 是报文发送频率。CAN-H/CAN-L 接对应信号，供电与共地按设备手册确认，不把采样功率端接到 CAN 信号端。

| 数据字节 | 解释 |
| --- | --- |
| Data0 / Data1 | 电压低 / 高 8 位，合成无符号数后除以 100，单位 V |
| Data2 / Data3 | 电流低 / 高 8 位，当前按无符号数除以 100，单位 A |
| Data4–7 | 协议未说明，暂不解析 |

只接受标准数据帧、DLC 8；扩展帧、远程帧和 FD 帧不作为功率计数据。电流原始值 200 对应 2 A；若电压为 24 V，则计算支路功率为 48 W。电流符号、传感器内部采样/滤波延时及校准精度仍需厂家资料或实测确认。

测四个底盘电机合计输入功率时，把采样部分串在这四个电调共用的供电支路，避免同时包含云台、摩擦轮和其他负载。单只表不能分出四个电机各自电流；电池侧若跨过超电容或其他电源转换，也不能直接等同四电机功率。当前仅用于接收、记录和对比模型，不接管功率闭环。记录字段、丢样本判断和对照步骤见[日志说明](../../manual/调试与日志.md#can-功率计与模型对照)。本次尚未接入实物验证。

## DBUS 接收机

UART5 使用 DJI DBUS 的 18 字节遥控帧。旧遥控器的第五路 CH5 可能失效或固定输出 0；当前仅校验前四个摇杆通道，DBUS 的第五路固定按中立值处理，不参与控制，也不影响整帧有效性。两个拨杆、鼠标按钮的合法性检查、遥控超时和启动安全档确认仍然保留。

此兼容只作用于 DBUS，ELRS/CRSF 和图传输入的第五轴不受影响。原始遥控日志仍保留收到的 CH5 数值，便于排查旧接收机；控制快照中的第五轴为 0。

## ELRS 接收机

当前配置保留 UART5 的 SBUS/DBUS 接收，同时将 UART7 分配给外置 ELRS 的 CRSF 接收，UART7 不再启用裁判系统。UART7 的 PE7 是 RX、PE8 是 TX，速率固定为 420000。接线时将 ELRS 接收机 TX 接 PE7，并与控制板共地；当前固件只接收 CRSF 的 0x14 链路统计和 0x16 通道帧，不向接收机发送遥测，因此 PE8 可以暂不接。

MC02 原理图中 UART7（P13）和 USART10（P15）的 1 脚均为 `VCC_5V`、2 脚为 GND，共用 PC15 高电平开启的外供 5 V。HERO-M 的 `[features] external_5v = true` 在正常启动和桌面观测版中自动开启该电源；两路受控 24 V 仍保持关闭。静态准备、接收专用及音乐专用构建不自动开启外供电；使用这些构建测试接收机时需另外提供合适电源并共地，避免把外部 5 V 与板上输出直接并联。其他车型未声明此项时仍默认关闭。

2026-09-11 桌面实测：原固件未开启 PC15 导致接收机不亮，补齐此配置并烧录后，读回 PC15 高、PC13/14 低，用户确认接收机指示灯已亮。供电恢复不代表已经完成对频或通道验证。

MC02 分配给 `elrs_crsf` 的串口由配置生成器自动启用硬件 FIFO 缓冲，随角色移动到 UART7 或 USART10；不修改其他串口角色。实测原单字节接收在 420000 波特率下会因短暂中断延迟出现硬件溢出，随后按保护逻辑重启接收、撤销输入。FIFO 为硬件接收保留缓冲余量，错误重同步、CRC 校验和断链撤销仍保留。观测时比较连接稳定后的计数增量，不把接收机上电期间已经累计的帧/噪声错误当成持续故障。

ELRS 只有持续发送有效链路统计和通道帧才会成为控制来源；链路统计超过 250 ms 未更新会撤销该来源。首次上电前将遥控器的安全档、底盘档和射击档设为安全位置。先使用接收专用构建确认 UART7 接收、通道映射和断链撤销，再进行任何控制输出验证。

`ConfigInput.inc` 当前 ELRS 映射为 CH1–CH4 和 CH7 对应五个逻辑轴，CH5、CH6 对应两个逻辑拨杆。遥控器模型应按此分配；未在实物上确认方向前不修改该映射。

## 桌面温度与零漂观测

`projects/HERO-M/bench.conf` 保留正常 HERO-M 控制任务，适用于已经断开电机的桌面单板。UART8 的 PE1 接电脑串口 RX，PE0 接电脑串口 TX；串口为 115200。板上 IMU 仍以 40°C 为温控目标、2% 为加热占空比上限；仅 DAP/USB 供电时不能据此判断 24 V 加热性能。正常固件只在 RAM 中修正开机零偏，不写内部 Flash 校准区。

在 `projects` 目录执行（本机工具链使用 `hero-m-local`）：

```powershell
cmake --preset hero-m-local -B ../local/build/hero-m-bench -DEXTRA_CONF_FILE=D:/ARBATOS/projects/HERO-M/bench.conf -DEXTRA_DTC_OVERLAY_FILE=D:/ARBATOS/projects/HERO-M/music.overlay
cmake --build ../local/build/hero-m-bench --parallel 2
```

两个追加配置必须同时保留：`bench.conf` 打开观测，`music.overlay` 将控制台接到 UART8。这里复用串口引脚文件，不会打开音乐专用启动模式。烧录前须确认目标为 HERO-M、应用不超过 `0x080C0000`，按应用扇区擦写并回读验证；不做全片擦除。

仓库根目录用 `tests/ZephyrMusicM/CaptureBench.py --port COM12 --output <日志路径> --seconds 600` 只读采集，实际 COM 号以本机枚举为准；结束后用 `tests/ZephyrMusicM/AnalyzeBench.py <日志路径>` 导出 CSV 和分析结果。脚本须通过带 pyserial/numpy 的 Python 运行。移动、重新上电和中断采样分别标记，不把跨动作的角度变化当零漂。

| 记录 | 字段及单位 |
| --- | --- |
| `@IMU` | 毫秒、IMU 毫摄氏度、三轴微弧度/秒、yaw/roll/pitch 微弧度、三轴毫米/秒²、加热 PWM、校准完成状态 |
| `@BIAS` | 毫秒、三轴补偿量（微弧度/秒）、正在校准状态 |

| `@SD` | 毫秒、是否写入、已写字节、丢记录数、错误码 |

| `@ELRS` | 毫秒、串口启动状态、链路状态、质量、通道帧数、统计帧数、发布数、CRC 错误、长度错误、溢出、接收重启、统计超时 |
