# ARBATOS 桌面客户端

这是仓库内的本机工程工具：编辑车型、PID、中位、电机、舵机和遥控映射，分配板载接口，读取串口曲线，解析 SD 日志、转换歌曲，并为单一车型执行检查、编译和确认后的烧录。界面借鉴了 [Betaflight App](https://github.com/betaflight/betaflight-configurator) 的紧凑工具布局；没有复制其源码、资源或协议实现。

客户端不连接云端。桌面进程启动一个仅绑定 `127.0.0.1` 的 Python 服务，页面通过本次启动的随机会话令牌访问它；服务再调用仓库已有的生成器、构建脚本和串口服务。

## 启动

在仓库根目录双击 [打开客户端.cmd](../打开客户端.cmd)。它会：

1. 优先使用 `local/cache/zephyrproject/.venv/Scripts/python.exe`，没有时使用 PATH 中的 Python；需要 Python 3.12 或更高版本。
2. 首次缺少依赖时安装 `client/backend/requirements.txt` 中的 `pyserial`、`tomlkit` 与 `PyYAML`。
3. 首次缺少桌面运行程序时运行 `npm ci` 和 `npm run setup:desktop`，再运行 `npm run build`。需要 Node.js 24 和 npm；首次安装需要联网。
4. 启动 Electron 桌面窗口及本机服务。

首次安装也可手动执行：

```powershell
cd D:\ARBATOS\client
python -m pip install -r .\backend\requirements.txt
npm ci
npm run setup:desktop
npm run build
npm start
```

`npm start` 需要先有 `dist/`，并从 `client/` 目录运行。需要指定 Python 时，可先设置 `ARBATOS_PYTHON` 为 Python 可执行文件的完整路径。

## 目录和职责

| 位置 | 职责 |
| --- | --- |
| `src/` | Vue 3 页面；只通过 `src/api.ts` 调用本机 RPC。 |
| `desktop/` | Electron 窗口、服务启动与关闭确认。 |
| `backend/` | 车型、文件、任务和串口 RPC；不向外网开放端口。 |
| `scripts/test-backend.mjs` | 启动后端单元测试的 npm 入口。 |

接口按用途分为 `workspace.summary`、`robot.*`、`config.*`、`ports.get`、`file.*`、`tools.*`、`serial.*` 和 `job.*`。页面不直接读取任意路径，也不会用静态示例数据伪装真实串口或构建状态。

## 车型配置和文件

选择车型后，配置页可编辑控制器、服务和功能开关；完整配置可在文件页打开 `RobotConfig.toml`。保存前会带上读取时的修订号；外部修改造成冲突时后端会拒绝写入，不覆盖对方内容。修改可先做“检查修改”，保存后再编译。

“新建车型”按开发板、机构组、电机和遥控器生成离线配置，组合对应的任务与装配；高级入口保留整车复制。新副本设为单电机模式且不选择任何电机，核对接线、机械参数和方向后在 `ConfigOperation.inc` 显式启用输出。A、C 板都开放经典底盘、普通云台、发射、DBUS、ELRS 和裁判系统；向导分别按 A 的 USART1/UART8/USART6 与 C 的 USART3/USART1/USART6 写入实际端口。C 板模板默认关闭 SD 日志和完整 Watch，日志可按需启用后重新构建；两板都不开放尚未适配的轮腿、双水平轴云台、PWM 舵机和 RS485 组合。

经典四轮底盘可选自动、总指令、模型功率、模型与总指令四种限制策略；配置在“参数与设备”的功率组中保存，重新构建后生效。36000 是命令刻度绝对值之和的调试上限，不是安培或瓦特。轮腿控制器不读取这一组限制。总线舵机需要接入具体型号的协议，当前目录不会提供一个可运行的通用 UART 电机选项。

文件页只列出后端允许的、该车型目录中的现有文本文件。常见入口仍是：

| 内容 | 文件 |
| --- | --- |
| 车型能力、控制器和服务选择 | `Robotconfig/<车型>/RobotConfig.toml` |
| 电机型号、编号、总线和实例绑定 | `Robotconfig/<车型>/ConfigHardware.inc` |
| PID、限幅与运行参数 | `Robotconfig/<车型>/ConfigTuning.inc` |

客户端可以编辑这些现有文件，但在线参数保存通路还没有接入。串口连接用于查看和手动发送文本；它不会把 PID 或其他控制参数直接写入正在运行的固件。

后端还提供 `imu.mount` 与 `imu.mount.update`：读取或保存 `ImuMount.h` 的三条原始轴映射。保存只接受 24 种右手正交方向，并用文件修订号防止覆盖他人修改；先在 `RobotConfig.toml` 启用 `features.imu_mount`，保存后仍须重新编译和烧录，当前运行中的设备不会立刻改变方向。

“IMU”页面通过板子的 USB 虚拟串口观测三轴姿态、角速度、加速度和温度；串口选择文本模式。打开页面时按需订阅，离开后停止。零漂窗口按设备时间计算、处理角度跨越正负 180°，设备重启、零偏更新或长时间中断后重新统计；移动设备时得到的是运动趋势，需保持静止观察。界面中的“间隙”表示遥测时间不连续的次数，不是精确丢包数。

“开始校准并写 Flash”只对当前连接且车型匹配的板载 IMU 生效。设备先锁住输出，稳定温度并静止采样，再暂停 SD 日志和加热后写入、读回验证零偏双副本；匹配本次请求和新保存序号才显示成功。完成、失败或取消后都需人工重启才能恢复输出和日志。外置 HI14 与旧版固件不支持此入口。新增 A/C/M 手动写入流程尚待实板验收，页面和软件回归不能代替断电重启读回检查。

“参数与设备”按 PID 与中位、电机与传动、遥控映射、舵机分组，支持中文及原字段名搜索。表单直接修改现有 `Config*.inc` 的数值和枚举，没有另造一份参数表；宏和算式保留为只读，仍可去文件页编辑。保存会检查四份参数文件的修订号，保持原注释、编码和换行。保存后需要重新编译。

- 电机统一显示逻辑轴、型号、设备编号、CAN/RS485 总线、型号内置减速比和外置减速比。外置比 `0/1` 表示直连，大于 `1` 表示减速；型号内置比来自共享型号表。CAN MIT、Unitree 和 N6014 的命令与反馈做对应换算；RM 目前接入底盘四轮和云台，其他 RM 业务轴拒绝配置额外减速。换算按理想传动关系，机械效率和摩擦仍需实测。
- ELRS 物理通道显示为 CH1–CH16，统一手动输入显示逻辑轴 1–5；客户端负责转换代码里的从 0 开始编号。
- M 板舵机表提供 P11 四路 PWM、最小/中位/最大脉宽、反向、键盘步进或逻辑轴控制。需同时启用 SERVO 服务；安全锁定时关闭脉宽，遥控恢复或换来源后，轴控制先回中再恢复跟随。

## 接口与外置接收机

“车型与接口”只列出当前板级定义的物理串口。选口会写入本车 `RobotConfig.toml` 的 `[ports]`，生成器据此生成固件串口绑定和引脚配置，并检查重复占用及能力。第一次从旧配置选口，会一并保留已有接线；缺少板级支持的接口不会伪装成可用。

M 板外置 ELRS 使用 CRSF、420000 波特率，独立于 AUX 调参串口，可同时使用；当前接收通道和链路统计，不向接收机发送遥测。SPI/SX1281 实验源码继续保留。调参 AUX 使用现有 `AuxTune` 协议、230400 波特率；选择调参口只是接通固件接口，客户端目前仍以离线参数编辑为主。

外置陀螺仪支持超核电子 **HI14 UART（3.3 V TTL，115200、8N1、HI91/0x91 数据帧）**。在“外置 IMU”选口后启用 HI14 姿态源，留空使用板载陀螺仪。串口号与波特率配置不会替传感器发送设置命令；传感器需输出匹配的数据帧。协议依据[超核官方用户手册](https://download.hipnuc.com/products/imu/cum.html)。

HI14 数据换算到项目的加速度、角速度和四元数接口，沿用统一日志和快照。外置模块默认正装，传感器轴要和机器人轴一致，不能套用主板 BMI088 的安装旋转；模块的世界坐标/航向模式应事先核对。外置源不运行板载加热或零偏保存；坏帧、未收敛状态、重复设备时间和断流不能持续刷新有效姿态，也不会自动退回板载源。实物接线、姿态方向、输出速率和失联保护仍需接到设备后验证。

## 日志与音频

- SD 日志：导入当前 `.bin/.lz4` 文件，检查文件头、数据块、LZ4 和 CRC32，预览最多 128 个数值字段、每条最多 1200 个抽样点。完整已解析数据可导出：单组为 CSV，多组按组生成 CSV 并打包为 ZIP；未识别记录单独计数。每个上传文件最多 24 MiB，解压数据最多 64 MiB、记录最多 500000 条。
- 歌曲：输出副板使用的无文件头、12 kHz、单声道、无符号 8 位 PCM `.u8`。自动使用 PATH 中的完整 ffmpeg，或仓库 `tools/Mp3ToU8/ffmpeg.exe`；仓库精简版只支持 MP3，PCM WAV 由 Python 转换。完整 ffmpeg 可处理页面列出的其他格式。转换不会播放声音，结果由“下载 .u8”保存。

上传内容只发送到本机服务，临时音频转换文件在转换结束后清理。曲线标明离线抽样，下载日志包含完整已解析数据；它们不表示设备当前在线。

## 接收机

“接收机”页借鉴 Betaflight 的[通道查看与映射](https://betaflight.com/docs/wiki/app/receiver-tab)和[拨杆模式](https://betaflight.com/docs/wiki/app/auxiliary-tab)组织方式，显示机器人自己的轴、模式和校准功能。没有复制 Betaflight 源码，也不使用飞行器的 ARM 等模式。

- **实时通道**：显示 CH1～CH16 的 CRSF 原始值和当前车型文件里的用途。常用标尺为 172 / 992 / 1811；通道可复用，没有映射的通道明确标注。
- **功能分配**：先把物理 CH 映射到 5 个逻辑轴、2 个逻辑拨杆，再分配底盘、云台、发射和校准功能；可逐功能反向。与“参数与设备”共用配置修订检查和保存入口。
- **拨杆模式**：编辑现有安全、普通、小陀螺、停火、预热和开火档位。未反向时，原始值 ≤582 为下档，583～1400 为中档，≥1401 为上档。匹配提示仅预览文件配置，不代表机器人已执行动作。

MC02 当前桌面观测固件通过 UART8、115200、文本格式输出数据；ELRS 接收机本身接 UART7，两个串口用途不同。页面与“串口与曲线”共用同一个连接，不自动打开串口，不发送遥控或参数命令。需要启用 `projects/HERO-M/bench.conf` 的观测输出；普通固件若没有这些输出，页面会等待数据。

观测帧为 `@RC,ms,last_frame_ms,valid,sequence,ch1,...,ch16`，约 10 Hz；两个时间都是设备绝对毫秒，通道为 0～2047 的 11 位原始值。`@ELRS`、`@UART`、`@INPUT` 提供约 1 Hz 的链路、串口累计错误和实际输入来源。页面同时检查固件有效标志、设备帧年龄和本机接收时间；暂停、断流和断开时不能把旧值显示成实时输入。

保存仅修改所选车型文件，重新编译、烧录后才进入固件；页面尚未读取设备内的配置版本，用途和档位展示始终标明来自文件或草稿。

## 串口与曲线

客户端默认只枚举本机 COM 口，不会自动打开或发送。连接时选择 `text`、`csv` 或 `justfloat`，以及 1 至 16 个通道；连接期间格式和通道数锁定。文本发送固定使用 LF 行结尾。

- `text`：按文本行显示。
- `csv`：每行 N 个逗号分隔的数值，或首列时间加 N 个数值，N 为选择的通道数。
- `justfloat`：每帧 N 个小端 32 位浮点数，末尾为 `00 00 80 7f`；N 为选择的通道数。
- CSV 离线回放：只接受最多 5 MB、100000 行、1 至 16 个数值通道的文件。可选首列时间表头为 `time`、`time_s`、`timestamp`、`tick_ms` 或 `time_ms`；后两者自动转换为秒。普通列名表头也可用。空值、非数值、列数不一致和倒退的时间会被拒绝。

导入离线 CSV 前必须先断开真实串口，回放界面会明确标注“离线数据”。它不代表设备当前在线。

## 底盘装配与手转识别

“底盘装配”集中编辑经典四轮底盘的轮型、轮位、电机型号、总线、节点号、安装方向和减速比。X 形全向轮沿圆周切线绘制，麦轮按矩形底盘绘制；两种混控的后轮槽位顺序不同，页面和参数表都按当前轮型显示。方向预览只展示现有混控的目标符号，不向车辆发送指令。

图形编辑与“参数与设备”共用一份配置草稿及保存检查，仍写回原有 `ConfigHardware.inc`、`ConfigTuning.inc`，保留注释、编码和换行。交换两个轮位时可以先完成全部修改再一起保存。反馈 ID 根据型号和节点号自动预览，也支持显式反馈地址；“节点号”是软件绑定值，不会修改电机硬件设置。关闭单轮后仍可在装配页重新配置；未启用经典四轮控制器的车型不显示四轮图。

手转识别首版支持 `INFANTRY-TIAN-A` 的 UART6、115200 文本诊断，与已有串口监视共用连接。用户核对观测对应当前车辆、确认停机后，每次只手转选定主轮，连续采集 8 秒。页面只在收到停机状态、零命令和新鲜反馈时允许采集；每路至少两次反馈计数推进，且仅一条路由持续出现明显转速时给出候选。确认候选只加入离线草稿，方向仍需单独核对。

诊断里的 `id` 是固件内部电机实例号，`bus` 是固件路由配置；实际收到的反馈 ID 来自 `last_fb`。候选按所选 RM 型号的反馈基址换算节点号，不把内部实例号当作节点。现有诊断没有编码器角度，不能自动确认转向或发现未纳入固件路由的电机。暂停、断流、重连、诊断重启、退出停机状态、修改绑定字段或候选超过 30 秒时，旧识别结果作废。

客户端构建、配置保存及串口解析的电脑端测试，与真实串口、电机方向和整车运动验收分别记录。这里的参数保存仍需要随后编译、烧录；当前页面没有在线参数写入或电机主动测试通路。

## 编译与烧录

“检查”只检查当前车型的配置和工程引用；“增量编译”使用该车型现有构建目录；“重新编译”使用全量构建流程。客户端一次只对选中的车型启动任务，日志保留最近一段输出。配置或文件有未保存修改时，客户端会阻止开始构建，避免编译磁盘上的旧内容。

烧录不会直接开始。先请求产物计划，显示精确车型、固件路径、构建时刻和 SHA-256；确认后才启动下载。后端还会核对构建产物、当前源码状态和车型匹配。下载沿用仓库 `tools/build.ps1` 的正式 OpenOCD 参数，其中包含 `--no-erase --verify`：保留校准区，且写入后校验；不要改成整片擦除后再把这项保护当作仍然存在。

客户端的编译、计划和本机服务已做电脑端检查；真实电机、下载器、校准数据和整车硬件尚未用此客户端完成实测。烧录和上车仍按 [调试与日志](../manual/调试与日志.md) 的硬件准备步骤执行。

## 开发与测试

前端按状态的归属拆分：`App.vue` 负责导航、页面组合和文件编辑；`useConfigEditor.ts` 管理车型与参数草稿、修订检查和保存；`useSerial.ts` 管理串口连接、采样与回放；`useBuild.ts` 管理构建任务、日志轮询和烧录确认。各模块自己清理定时器，共用类型放在 `types.ts`，CSV 解析放在 `serialCsv.ts`，后端接口保持不变。

“车型与接口”中的完整 Watch 变量镜像默认关闭，启动阶段记录和故障处理继续保留；勾选后重新编译可恢复调试器的集中变量视图。SDLOG 服务控制日志任务与采样/压缩缓存是否编入，不影响音乐使用 SD 卡。取消服务时保留原有任务栈覆盖值，重新启用后恢复，未启用任务的覆盖值不分配内存。点击“检查修改”可查看草稿最终带入的任务、依赖原因和声明栈大小。

“内存与 Flash”从当前车型本地最近一次构建的 ELF 和 map 读取实际段分配，显示主 RAM、Flash、DTCM 等区域的模块分布与尾部余量，排除被丢弃的代码和调试段。数据段的 Flash 初始值和 RAM 运行副本分别计入；对象归类属于推断，无法归属的对齐和链接器内容单列。页面显示构建时间和固件校验值，尚不读取板上固件身份或运行时栈余量。未构建的功能选择需重新编译后才能看到空间变化。

“具体变量、任务栈与函数”继续展开到 ELF 符号，支持搜索名称、区域和所属段，显示每项字节数及运行地址。栈、堆和缓冲区按预留容量展示；未命名内容不包含在明细表内，相同地址和尺寸的别名只保留一次，区域总量仍以段分配为准。

关闭 SD 日志后，致命异常证据仍会写入备份 SRAM，原有故障重启锁保持。因为不再自动把证据写入 SD 并确认，发生该类异常后需人工检查和处理，单纯重启不会清锁。

```powershell
cd D:\ARBATOS\client
npm run build          # Vue 类型检查和生产构建
npm run dev            # 仅启动 Vite 开发服务；不启动本机 RPC
npm run test:backend   # Python 后端单元测试
node --experimental-strip-types --test tests/receiver.test.mjs # 通道映射与失效判定
pwsh -NoProfile -File ..\tools\client\StartClient.ps1 -BuildOnly
```

以上命令验证页面构建或后端逻辑，不能替代实际串口、下载器和车辆测试。

开发界面时，先在一个终端启动后端：

```powershell
python .\backend\server.py --port 8765 --dev-origin http://127.0.0.1:8766 --session-file ..\local\cache\client\dev-session.json
```

再在另一个终端运行 `npm run dev`。浏览器打开 `http://127.0.0.1:8766/#token=<dev-session.json 中的 token>`；令牌只用于当前本机服务，文件在退出后移除。Vite 将 `/api` 转发给后端。改前端端口时同步修改后端 `--dev-origin`；改后端端口时设置前端环境变量 `ARBATOS_API_URL`。

界面调用 `POST /api/rpc`，请求为 `{ "method": "robot.get", "params": { "target": "HERO-M" } }`，通过 `Authorization: Bearer <token>` 验证会话。成功返回 `{ "ok": true, "result": ... }`，失败返回 `{ "ok": false, "error": { "code": ..., "message": ... } }`。后端独立校验路径、修订号和参数；更换前端时继续使用这份接口，不需要重写配置生成或下载逻辑。
