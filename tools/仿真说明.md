# 仿真说明

这里有两类用途不同的工具：`tools/sim/RobotSim.py` 做配置与总线压力估算，`tools/mujoco/wheelleg/RunWheelLeg.py` 做轮腿控制核心接入 MuJoCo 的物理仿真。两者都不能替代实车验证。

## 配置估算

`RobotSim.py` 读取 `projects/prj.conf`、`projects/<PROJECT>/prj.conf`、`Robotconfig/<PROJECT>` 和共享配置，估算电机报文、CAN 总线分布、1000 Hz 反馈压力、RM/DM/MIT 指令帧、每毫秒调度限流、接收队列积压和粗略 CPU 压力。

在仓库根目录运行：

```powershell
.\tools\build.ps1 -Action sim -Project MINIWHEELEG-M
.\tools\build.ps1 -Action sim -Project all
python .\tools\sim\RobotSim.py --project HERO-M --json
```

常用选项：`--duration-ms 2000` 延长调度模拟，`--can-tx-period-ms 2` 试算指令周期，`--motor-feedback-hz 1000` 设置反馈频率，`--rx-us-per-frame 6 --tx-us-per-frame 8` 设置 F407 的单帧处理时间，`--fail-on-risk` 在报告有警告或失败时返回非零。

它用于烧录前发现配置层面的压力。CPU 数字是估算，需结合真实 `RtProf` 日志判断；它会按 ARM/MIT 路由与 Shoot 预算过滤，同时仍计入已配置 RM 电机组，因为固件可能发送零电流组帧。

## MuJoCo 轮腿物理仿真

运行器根据 `Robotconfig/<project>/RobotConfig.c` 生成五连杆轮腿模型：自由基座上的接地轮、前后主动关节、被动膝关节与闭链约束，并通过一个包含 `WheelLegCore.h` 的本地 C 桥接层调用可复用控制核心。

先安装 Python MuJoCo 与一个 C 编译器：

```powershell
python -m pip install mujoco
```

Windows 可使用提供 `cl` 的 MSVC Build Tools、提供 `clang` 的 LLVM、提供 `gcc` 的 MinGW，或 Zig。首次运行会在 `local/cache/mujoco_wheelleg/` 生成 MJCF，并生成 `arbatos_wheelleg_core_bridge.dll`；这些可重新生成的文件不提交，工具源码仍放在 `tools/`。

```powershell
# 只检查 MJCF 与项目配置，不需要 MuJoCo 或 C 编译器
python .\tools\mujoco\wheelleg\RunWheelLeg.py --check --project MINIWHEELEG-M

# 台架 PID / VMC 输出
python .\tools\mujoco\wheelleg\RunWheelLeg.py --project MINIWHEELEG-M --bench --leg-branch diamond --viewer --realtime
python .\tools\mujoco\wheelleg\RunWheelLeg.py --project MINIWHEELEG-M --bench --vmc --leg-branch diamond --viewer --realtime

# 打印模型参数，或改用自定义 MJCF
python .\tools\mujoco\wheelleg\RunWheelLeg.py --project MINIWHEELEG-M --print-params
python .\tools\mujoco\wheelleg\RunWheelLeg.py --project MINIWHEELEG-M --model .\tools\mujoco\wheelleg\WheelLegMinimal.xml
```

默认 `diamond` 分支对应预期的五连杆外形；`--leg-branch core` 用于对照旧控制核心的初始化分支。加 `--keyboard --viewer --realtime` 后，上下方向键调目标速度，左右方向键调 yaw 角速度，`Q`/`E` 调目标腿长，`Z`/`C` 调目标足端 x，`X` 清零速度、yaw 和足端 x 目标。

该模型可检查 MuJoCo 安装、传感器符号、轮端力矩方向、五连杆几何与基本接地、台架 PID/VMC 输出，以及控制核心是否能脱离固件调度器运行。几何和控制增益来自 `RobotConfig.c`，质量假设见 [轮腿参数计算报告](WheelLegLqr/轮腿参数计算报告.md)。轮距、轮宽、接触材料、关节阻尼、详细转动惯量仍是仿真假设；`diamond` 分支的 VMC 站立还需实物电机方向、零位和接触参数校准。

### 自动记录与失败基线

`EvaluateWheelLeg.py` 对自由三维和二维模型各运行站立、前进、后退三种场景，复用现有 `--vmc` 桥接控制。默认每段 10 秒，先站立 2 秒，再给 ±0.15 m/s 指令；提前倒地时明确记录没有执行到速度指令。输出 `summary.json`、逐周期 `trace.csv` 和本次生成的 MJCF，并记录控制源码、配置与模型的 SHA-256。通过返回 0，验证失败返回 1；失败不等于脚本异常。

```powershell
# 本次排查的独立环境；不改 Zephyr 构建环境
& .\local\cache\wheelleg-audit-20261003\.venv\Scripts\python.exe `
  .\tools\mujoco\wheelleg\EvaluateWheelLeg.py `
  --output .\local\cache\wheelleg-audit-20261003\baseline
```

换机器时可在独立 Python 3.12 环境安装 `mujoco==3.14.0` 后运行上述脚本。仍需前述 C 编译器。记录包含机身原点的实际前向速度、核心估计速度、姿态、漂移、腿长、六路请求力矩、轮力矩限幅占比和闭链端点距离。CSV 在施加本周期命令前采样，末行是停止时的状态与尚未施加的命令。

默认失败条件是俯仰或横滚超过 45°、机身高度低于轮半径加 25 mm、闭链误差超过 10 mm、数值异常。完整运行后还要求站立漂移不超过 0.10 m，最后一段实际速度对目标的均方根误差不超过 0.05 m/s（从第 3 秒开始统计）。这些是可调整的早期排查阈值，不是实车验收标准。`--planar` 锁住横滚和偏航，`--drive-plane` 连俯仰也锁住，后者不进入站立评价。

2026-10-03 使用 MuJoCo 3.14.0、3 ms 步长、当前 `MINIWHEELEG-M` 配置、默认轮力矩比例 1.0 实跑：自由三维在 **0.705 秒**、二维在 **0.651 秒**超过 45°，前后行驶指令均未执行到。原始结果在 `local/cache/wheelleg-audit-20261003/baseline/`；生成物位于忽略目录，不随源码提交。此次没有改控制增益、电机零位或固件，也没有连接硬件。

### RM 开源整车：已跑通的参考

由于 MINIWHEELEG-M 的机械设计尚未定型，先独立运行 [CosmosMount/wbr_mujoco](https://github.com/CosmosMount/wbr_mujoco)，固定提交 `81a1035e66315a46abd1f0ca4c11ec40596b95c5`。这是约 16.015 kg 的 RM 双轮腿整车，包含车身、云台、网格、惯量、四个腿内闭链连接和六路执行器。上游已经提供 MuJoCo 原生 MJCF，可直接保留闭链，不需要先转 URDF。另一个含 URDF 和 MJCF 的候选是 [RMInfantry_wheelLegged_ws](https://github.com/chen-jiangnan/RMInfantry_wheelLegged_ws)，本轮没有安装它的 ROS2 环境或声称跑通它。

第三方文件保留在 `local/reference/wbr_mujoco/`，本轮未修改其模型、控制算法、参数或初始姿态。新增的 `tools/mujoco/reference/WbrBridge.cpp` 直接编译上游 `balance.cpp`、`leg.cpp` 和 `chassis_fsm.cpp`，按原 `services.cpp` 的执行顺序接入原始仿真传感器。配置与上游 YAML 逐项对应，运行器检查提交和配置哈希，并拒绝控制或模型目录中的本地修改。

本地接口使用上游已有的 IMU `bypass` 模式，即直接使用仿真四元数；控制与物理周期均为 1 ms。测试脚本直接提供速度指令，位置参考按原命令处理逻辑积分，省去原项目的键盘、eCAL 通信和多线程服务。车身始终是六自由度，只有腿内闭链约束，没有外力支撑；初始姿态使用上游 `home`，由原状态机自行撑起。

### RM 机械模型接入本项目控制核心

`RunOwnWbr.py` 已直接编译本仓库的 `WheelLegCore.h`，复用其中的运动学、速度观察器、LQR 输出、PID、VMC、横滚和转向计算。主机侧 `OwnWbrBridge.c` 负责传感器坐标变换、两腿同步与目标编排；构建不包含上游 `balance.cpp`、`leg.cpp` 或 `chassis_fsm.cpp`。MINIWHEELEG-M 的实车参数未改。接入位置阶段时，Core 正解辅助函数允许合法的零髋轴间距（`l5 == 0`）；其原有数学表达式、原车型正间距计算及动力学计算路径不变。

批量入口 `RunOwnWbr.py` 使用原始 MJCF、网格、质量、摩擦和电机限幅。初态由 `DesignOwnWbr.py` 独立求解闭链、腿长、轮高及重心位置，释放时机身即为六自由度，没有外部固定或支撑。此批量入口从直立姿态开始；下述浏览器入口另有从原模型 home 低姿态起身和 6216P 电机限幅。控制周期 3 ms，物理周期 1 ms，中间保持电机力矩。

模型适配明确区分以下约定：

- 两侧统一为同一纵向坐标；反射足端横坐标后交换虚拟前后支链，关节力矩按同一映射的转置转换。实际等效杆长约为 0.215/0.254 m，髋轴共轴；轮碰撞半径约 0.058 m，目标腿长 0.20 m。
- 轮子安装在活动下连杆上，由电机编码器、核心的 `phi3` 变化及 IMU 修正轮绝对角速度，再传入原速度观察器。控制器不接收 MuJoCo 的机身位置、速度或雅可比真值；真值只用于离线设计和独立评价。IMU 使用无噪声仿真四元数与角速度，没有执行实车姿态融合。
- 平衡增益按原模型质量、惯量、闭链与理想滚动约束重新计算，使用两腿共同运动的六状态。两腿角度差另外用原 PID 计算并施加相反髋力矩，避免各侧平衡力矩抵消转向输出。位置参考随速度指令积分，停止后保持，指令加速度限制为 0.4 m/s²。

`OwnWbrProfile.json` 保存重新计算的增益、初态和设计证据。离散控制周期 3 ms；状态权重为 `[80, 1.5, 40, 200, 1000, 20]`，输入权重为 `[1, 0.5]`。约束独立秩 17，约化质量矩阵正定，六状态连续与离散系统可控秩均为 6，局部加速度线性化探针相对误差约 0.013%。固定腿长模型忽略了接触软化及库仑摩擦，这些保留在最终非线性 MuJoCo 测试中。

### 短腿扭矩与最短限位核对（2026-10-04）

用户确认实车最短腿处有挡块，但髋轴到轮轴的具体距离未知，初轮核对先保留参考模型的膝关节限位。**约 176 mm 是原始 MJCF 膝关节角度范围折算出的仿真下界，尚未证实为实体挡块位置。** 2026-10-05 复核发现，同一上游仓库控制器的 `lmin` 为 160 mm，CAD 零角装配按坐标计算约为 120 mm；参数之间存在需要核对的差异，不能据此断言实车收不到更短。现已加入明确标记的 `cad120` 参考范围并用于当前网页，见前文“短腿前送与台顶驻车”。界面 180 mm 是普通目标值，并不代表已经接触挡块。限位只能在受压时分担载荷，若气弹簧把腿向外推，需先克服弹簧才能压住最短限位。压住后仍需控制整腿角度、俯仰和左右平衡，不能把四髋电机视为完全无载。

### 气弹簧推力扫描与180毫米挡块（2026-10-11）

用户补充最短挡块腿长为 **180 mm**。本轮离线扫描按此设置左右被动膝的收腿端点，先由闭链静态姿态校验髋轴到轮轴的机构平面距离确为180 mm；不把之前的CAD零角120 mm参考范围当作实车挡块。实体挡块以关节限位近似，记录的限位反力为 **N·m广义反力矩**，不是挡块表面的牛顿力。网页和固件尚未套用本轮候选参数。

`SweepWbrGasSpring.py` 使用自有 `OwnWbrBridge.c` / `WheelLegCore`，四髋执行器全过程限10 Nm，轮端沿用5.2 Nm；质量、网格、碰撞修正、两侧被动导轮和参考静摩擦保持一致。物理步长1 ms、控制步长3 ms。气弹簧物理推力与控制器补偿同时改成同一数值；仍为每腿一根恒推力近似，尚无实物推力—长度—温度曲线，扫描的N数不能直接等同于购买时的标称F1。

主扫描覆盖每根0 / 200 / 250 / 300 / 350 / 400 / 450 / 500 N，目标腿长180 / 200 / 220 / 240 / 260 / 280 / 300 / 320 mm，以及额外的180 mm挡块卸载工况，共72组。每组独立创建模型和控制器，从相同闭链姿态、零速度释放，运行70秒，统计10～70秒。此处检验站立持有，不包含起身与跳跃，也不能视为电机已经达到热平衡。

- 普通站立保留原控制器每腿78.7046 N支撑前馈和全部平衡控制。
- 挡块卸载只改变初始化支撑前馈，取 `min(0.1701588×F, 67.1321) N/腿`。弱簧时让电机轴向承重分量接近零；强簧时压住过量助力，理想轴向计算留5 N/腿预载。腿长环、腿角控制、横滚差动和轮端平衡继续工作，运行中不以接触真值改变控制器。实际载荷由限位反力核对，5 N只是设计余量，不冒充已测得的承载。
- “站稳”“腿长误差5 mm内”“持续双侧挡块承重”“电机有限幅余量”分别统计。无弹簧普通站立即使没倒，若四髋持续饱和10 Nm，也标为无余量并排除优选。挡块模式只在双侧短端反力都持续存在时算承重；普通模式若依靠挡块，不能混入自由站立最优。

主要热负担指标为 `H=Σ mean(τ_i²)=Σ τ_i,RMS²`，单位Nm²。四个电机相同、温度与电流定义一致时，该值与扭矩电流引起的铜耗成正比；均值、有效值、峰值、限幅占比和机械功率均单独保存。静止时 `τ×ω` 接近零，不表示电机不耗电。若以后确认输出轴扭矩常数 `K_RMS [Nm/A]` 与绕组每相电阻 `R_phase [Ω]`，则三相铜耗为 `P_Cu=3 R_phase H/K_RMS²`，持续`t_h`小时的铜耗电能为 `P_Cu×t_h Wh`；其他电流/电阻定义必须先换算。

[6216P官方资料](https://www.damiaokeji.com/index.php?c=show&id=144)给出10/45 Nm、1:16减速比和标注为“相电阻”的0.16 Ω，但未明确本轮需要的输出扭矩常数与电流峰值/有效值、电阻测量端点。因此本轮不编造四髋绝对A、W、Wh或温升。两轮另保留仓库3508拟合电功率，不能与Nm²直接相加，也不当作整车电池输入实测。
