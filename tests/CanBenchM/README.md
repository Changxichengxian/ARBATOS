# MC02 CAN 台架测试

当前为**已烧录、完整回读一致，已完成通信实测和手动辨位，六台均反馈失能**。测试对象已由用户确认：MC02、CAN1、1 Mbps、达妙电机 ID 1–6。后续本轮手动摆杆确认右前 2、右后 1、左前 4、左后 3；分别短转后用户确认右轮 5、左轮 6 及前进方向。详见[小轮腿安装说明](../../Robotconfig/MINIWHEELEG-M/安装说明.md)。精确机械零点仍未标定，初始近似水平姿态不冒充精确基准。

此工程独立于整车程序，上电只接收 CAN。本轮通过 UART8 无线串口收发测试命令及结果，计时在 MC02 上完成，不把无线链路延迟算成电机响应延迟。SWD 读取入口仍保留。未启动轮腿、轮速或姿态控制任务，也不写电机零位、安装参数或 IMU 校准区。

## 测试内容

| 项目 | 行为 | 结果 |
| --- | --- | --- |
| 静默观察 | 5 秒，仅接收 | 当前有效帧速率与估算占用 |
| 使能/失能 | 六个 ID 逐个各 10 轮 | 每次提交次数、入队次数、发送完成次数、状态确认时间、失败状态 |
| 通信负载 | 保持失能，以总计 100/500/1000/2000/3000 帧每秒分档发送失能帧，每档 2 秒 | 实际收发帧率、估算占用范围、接收溢出、发送失败及总线错误计数 |

重试间隔 5 ms，每次状态切换最多等待 100 ms。先逐个确认六台失能，再做使能测试；一次失败即停止后续使能，并补发失能。每轮使能前发送一次 MIT 编码零值、`kp=kd=0`，用于清除旧目标；零值编码有协议量化误差。这要求电机的实际控制模式是 MIT，测试不负责切换电机工作模式。

成功依据是目标 CAN ID 在命令之后返回的完整 8 字节反馈中，状态高四位为 1（使能）或 0（失能）。无回应、故障码、仅总线 ACK、旧反馈都不算成功。本轮六台均返回符合该规则的反馈；换电机或固件后仍需核对，不自动放宽成功条件。

次数统计是软件提交/重试次数，驱动发送完成表示总线发送得到确认，不等于能观测到每一次硬件自动重发。拥挤程度根据收到的有效帧和发送完成计数计算上下界，包含标准帧开销和填充位范围；不包含未接收成功的错误帧和不可见的硬件重发。它不是示波器测得的精确占用率。负载档位为请求速率，报告使用实际速率，不能拿请求值代替实测值。失能报文负载测试也不能直接代替整车运动任务的时序验收。

## 入口

在仓库根目录执行，编译、烧录、观察、测试互相独立：

```powershell
# 仅编译，不连接硬件
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py build

# 仅运行电脑上的回归测试
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/TestCanBench.py

# DAP 可用后才执行。首次覆盖未知旧程序前需确认 SD 已取下。
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py flash --probe 288485685068 --sd-removed

# 本次用户明确要求不备份；只擦写应用所在扇区，仍核验完整应用程序回读。
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py flash --probe 288485685068 --sd-removed --skip-backup

# 只读观察 UART8，115200、8N1；当前无线串口为 COM14
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py serial-listen --port COM14 --seconds 8

# 烧录成功后仍只接收；下面才开始实际测试，本轮使用此入口
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py serial-run --port COM14

# 备用 SWD 测试入口，不要与串口测试同时运行
.\local\cache\zephyrproject\.venv\Scripts\python.exe tests/CanBenchM/CanBench.py run --probe 288485685068
```

`run` 和 `serial-run` 均可用 `--test passive`、`--test transitions`、`--test load` 分别运行。正式测试仍由人与实物配合，不在 DAP 被其他人使用时自动重连或重试。

UART8 接线：PE1（主控 TX）接串口 RX，PE0（主控 RX）接串口 TX，共地，3.3 V 电平。串口命令以换行结束：`CB1 status` 仅查询，`CB1 passive` 静默观察，`CB1 transitions` 切换测试，`CB1 load` 负载测试；`!` 或 `CB1 stop` 请求停止，正在进行的主动测试会执行失能收尾。报告包含 5292 字节快照和 CRC32 校验，校验失败不接受为有效结果。无线串口刚打开时可能丢失状态行前半段，主机等待链路建立并重新同步报告头；不重发主动测试命令。

固件在 `local/build/can-bench-m-20261024/zephyr/`。默认烧录先保存板上完整 Flash，按扇区写入，完整回读程序并核对 `0x080C0000–0x080FFFFF` 校准区未变化。用户明确要求跳过备份时使用 `--skip-backup`：仍完整回读程序，不读取旧固件或逐字比较校准区，报告中校准区比较结果为 `null`。程序只占应用区；写入验证失败不自动运行。

无线 DAP 使用 100 kHz、单包传输，关闭调试器数据缓存。烧录前软件复位并暂停主控，以清除旧程序中断状态；直接暂停正在运行的旧程序后擦除，曾出现擦除完成后跳入 `0xFFFFFFFE` 的异常，补充复位步骤后烧录成功。

结果放到 `local/cache/can-bench/<时间>/`：`原始结果.json`、`统计结果.json`、`使能失能明细.csv`。位置字段附带交接来源，同侧前后位置继续待确认。不能把本机模拟回归数据填成实测结果。

## 手动姿态标定与单轮短转

V3 仍然上电只接收。新增 `CB1 sample`：逐台发送失能并等待新反馈，再报告六台角度；不使能、不修改电机零位。`CB1 left` 对 ID 6、`CB1 right` 对 ID 5 执行一次短转，两侧名称暂沿用交接记录，实际方向仍需操作者观察。

短转只允许 ID 5/6，开始前确认六台失能，清除旧目标，再使能目标轮。MIT 位置刚度为 0，速度目标约 ±0.752 rad/s，阻尼约 0.0305 N·m·s/rad，前馈力矩为编码零值。主控本地最多运行 1 秒；反馈超过 50 ms 未更新、反馈状态异常、速度超过约 2.5 rad/s 或位置变化超过约 1 rad 时提前停止。退出后立即清除目标、失能目标轮，再确认全部失能。串口中断不影响主控本地期限；`!` 可提前请求停止。此功能不驱动任何关节。

`watch --seconds 30` 只重复失能采样，逐次保存有校验的完整反馈。主机核对固件 V3 身份、六台计数均增加及六台失能，不把旧快照当当前姿态。

用户定义的初始姿态是“大腿杆相对机身接近水平”，机身本身是否水平未知，连杆也不是精确水平。该姿态用于识别 ID 和角度变化，不自动当永久机械零位；随后分开记录前侧两杆、后侧两杆接近竖直的姿态。机身水平和惯导安装偏置另行标定。
