## 历史恢复步骤（已推进，勿据此回刷旧固件）

1. 先检查供电和连接，暂不接24V，只用USB确认主控可连接；不能把DAP自身在线当成板子已供电。
2. 烧入上面的默认不加热准备版，全文读回校验后启动；确认低温时BMI088读数、ADC和RTC。
3. 通过读取邮箱先导出 `0:/HERO-M_0000.bin`，用 `tools/sdlog/SdLogDecompress.py` 检查完整块及CRC，区分异常断电造成的末尾残缺与传输损坏。
4. 由人在场接回24V，确认供电读数和温度后显式开启受限加热；板子固定，观察温稳、校准保存和日志写入。出现异常先关闭加热。
5. 停止并同步日志后读回校验；重启检查偏置加载、RTC走时和新文件命名。随后再回归音乐、两键及TIM5计时。
6. 上车后逐项核对IMU安装方向、遥控失联保护、CAN收发与电机ID、RS485方向、机械限位；先架空单电机，再低功率联动。本次没有启动这些动作，也不能宣布已具备实车运行条件。

调试工具 `PreflightProbe.py` 支持 `status / stop / list / read / warm / cool / rtc`，必须配套当前固件的 `.elf`。工具会先核对准备任务代码和诊断标识，避免把旧符号地址写入新版内存。目录与文件读取只读，`stop` 负责停止并同步日志，`rtc` 显式按电脑本地时间校时，正常启动不会重设时钟。
