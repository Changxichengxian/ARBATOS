# 坐标系和安装基准

这份文档只定项目里的坐标口径。每台车的实际安装位置和开发板朝向，写在 `Robotconfig/<TARGET>/MountLayout.md`。

## 通用正方向

除非某个接口单独说明，整车相关坐标都按右手系理解：

| 轴 | 正方向 |
| --- | --- |
| `+X` | 前方 |
| `+Y` | 左方 |
| `+Z` | 上方 |
| `yaw` / `wz` | 从上往下看，逆时针为正，顺时针为负 |

`vx` 对应 `+X`，`vy` 对应 `+Y`，`wz` 对应绕 `+Z` 旋转。

## 常用坐标系

| 名称 | 绑定对象 | `+X` 前方怎么定 | 典型用途 |
| --- | --- | --- | --- |
| 场地坐标系 | 启动或外部定位确定的地面基准 | 场地约定方向，或者上电时对准的方向 | 算法给固定地面方向的移动速度 |
| 底盘坐标系 | 底盘车体 | 车体正前方 | 底盘速度、轮速解算 |
| 云台 yaw 坐标系 | 云台水平朝向 | 云台 yaw 在水平面上的投影方向 | 算法按相机/云台看见的方向给移动速度 |
| 板坐标系 | 控制板本体 | 由开发板安装表说明 | 解释 INS 姿态到底跟着哪个机械部件 |
| 传感器原始坐标系 | IMU 芯片 | 由芯片和板级封装决定 | 只在板级 IMU 读取代码里使用 |

这里的“云台 yaw 坐标系”只看水平 yaw，不看 pitch。枪管抬头或低头，不改变底盘移动里的 `vx/vy` 平面方向。

## 两层安装关系

IMU 姿态要分两层看：

1. 传感器原始坐标 -> 开发板坐标
   这层属于 `boards/<BOARD>/`。例如 BMI088 芯片在某块开发板上怎么旋转，应该由板级 `InsTask.c` 或板级配置处理。

2. 开发板坐标 -> 车上某个机械部件坐标
   这层属于 `Robotconfig/<TARGET>/MountLayout.md`。例如主控板固定在底盘、大 yaw、小 yaw、云台还是轮腿本体上，以及开发板 `+X/+Y/+Z` 分别朝哪里。

不要把这两层混在一起。换一块开发板才变的东西放 `boards/`；同一块开发板装到另一台车上就会变的东西放 `Robotconfig/`。

## 和算法接口的关系

算法对接里的 `q[4]`、`yaw`、`frame=2` 都必须先看目标的安装表：

- 如果控制板固定在底盘上，INS yaw 更接近底盘 yaw。
- 如果控制板固定在大 yaw 上，INS yaw 更接近大 yaw 这一级。
- 如果控制板固定在云台上，INS yaw 更接近云台 yaw。
- 如果是双板，每块板都要单独写清楚，不能只说“板端姿态”。

`frame=0` 按云台 yaw 的水平朝向解释 `vx/vy`。
`frame=1` 按底盘车体解释 `vx/vy`。
`frame=2` 按板端姿态估计里的场地基准解释 `vx/vy`，只有 yaw 零点来源清楚时才建议算法使用。

## 安装表最少要写什么

每个 `Robotconfig/<TARGET>/MountLayout.md` 至少写：

| 项目 | 必填内容 |
| --- | --- |
| 控制板型号 | 例如 `DmMc02H7`、`DjiCF407`、`DjiAF427` |
| 控制板固定部件 | 底盘 / 大 yaw / 小 yaw / 云台 / 轮腿本体 / 其他 |
| 控制板正方向 | 板 `+X/+Y/+Z` 分别朝该部件的哪个方向 |
| IMU 姿态含义 | INS yaw/pitch/roll 主要代表哪个部件 |
| 云台层级 | 单 yaw、双 yaw、大 yaw/小 yaw/ pitch 分别是什么 |
| 相机和枪管 | 相机光轴、枪管方向和云台坐标是否一致 |
| 待确认项 | 没实测的不要硬写成结论 |

如果后面把安装关系做进 `g_config`，字段名也按这张表收敛，不要再让不同模块各写一套说法。
