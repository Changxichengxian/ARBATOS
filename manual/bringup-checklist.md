# 上车检查清单

这份清单用于第一次上车、换硬件、改控制链、改电机装配、改输入映射之后。不要跳过“无动力”和“反馈确认”阶段。

## 0. 上车前准备

- [ ] 确认当前代码分支、commit、是否 dirty。
- [ ] Keil Rebuild 通过，且 `tools/check_all.ps1` 通过；如果这次走 GCC/CMake，也确认 `tools/build.ps1 -Action gcc-build -Project <TARGET>` 通过。
- [ ] SD 卡可写，插卡后能生成新日志。
- [ ] 遥控器安全档位置确认。
- [ ] 摩擦轮、拨盘、底盘、云台能单独断电或物理卸载。
- [ ] 底盘架空，车轮离地。
- [ ] 现场有人能立刻断电。

如果 SD 日志里 `BUILD_INFO.build_dirty = 1`，记录这次上车是基于未提交代码。不是不能上车，但后面复盘时必须知道这一点。

## 1. 无动力确认

先不接高功率负载，至少确认：

- [ ] 状态灯有变化，不是卡死。
- [ ] `g_watch` 能看到任务计数在动。
- [ ] 遥控输入源在线，语义轴和开关变化正确。
- [ ] `SdLogGetStats()` 能看到日志 active，丢包为 0 或可解释。
- [ ] `RtProf` 没有明显超预算。

此时不看“手感”，只确认程序在跑、输入能进来、日志能留住。

## 2. IMU 检查

- [ ] 温控能到目标温度并稳定。
- [ ] 静止时 gyro 接近 0。
- [ ] 轻轻转动车体时 yaw / pitch / roll 方向符合预期。
- [ ] 姿态没有明显跳变。
- [ ] 正常上电微调或 `ROBOT_RUN_MODE_CALIBRATION + ROBOT_CALI_TARGET_IMU_GYRO` 路径明确。

IMU 不可信时，不继续调云台、底盘和轮腿。轮腿尤其不要在 IMU 不可信时给站立或平衡输出。

## 3. CAN 反馈检查

先确认反馈，再给输出。

- [ ] CAN 收发计数不是全 0。
- [ ] 每个电机在线状态正确。
- [ ] 手转电机时速度方向符合预期。
- [ ] CAN ID、反馈 ID、总线号、协议类型和电机型号对应。
- [ ] 不用的轴没有被误判在线，也不会收到输出。

反馈不稳定时先查线、终端电阻、ID、总线和协议，不要急着调 PID。

## 4. 单子系统动作

推荐顺序：

1. IMU 和输入。
2. 云台 yaw 单轴。
3. 云台 pitch 或第二 yaw 轴。
4. 底盘低速。
5. 摩擦轮。
6. 拨盘。
7. 裁判、视觉、日志、遥测。
8. 轮腿或机械臂实验。

每一步都用低限幅、小输出、短时间动作。确认以下内容后再提高输出：

- [ ] 正方向正确。
- [ ] 反馈方向正确。
- [ ] 限位正确。
- [ ] 遥控安全档能停。
- [ ] 断输入或失联能停。
- [ ] SD 日志里能看到命令、反馈和状态。

## 5. 轮腿 / MIT 电机额外检查

MIT 轮腿或达妙 MIT 模式不要直接进平衡实验。先按这个顺序：

- [ ] 单电机反馈在线。
- [ ] 使能 / 失能帧确认有效。
- [ ] 状态反馈能确认 enabled / disabled / fault。
- [ ] 单关节小幅位置或力矩动作。
- [ ] 单腿离地动作。
- [ ] 板凳模型或架空模型。
- [ ] 最后再做落地站立和平衡。

任何时候出现无反馈、IMU 不可信、腿长异常、遥控安全档、急停，都应该清零输出或进入安全阻尼。

## 6. 日志留存

每次有效上车至少留一份记录：

- target / board / commit / dirty 状态。
- 电池电压和主要硬件改动。
- 改了哪些参数。
- 测了哪些动作。
- 出现了什么异常。
- 对应的 SD 日志文件名。

推荐目录：

```text
local/logs/sdlog/<TARGET>/<YYYY-MM-DD>/
```

本地日志不一定进 Git，但至少要能在后面复盘时找到。

## 7. 结束后

- [ ] 把有价值的参数改回 `Robotconfig/<TARGET>/Config*.inc`。
- [ ] 重新 Rebuild，确认参数不是只停留在 RAM 临时值。
- [ ] 把关键结论写到 `local/docs/02_接入记录/` 或正式手册。
- [ ] 如果发现代码问题，先留日志和复现步骤，再改代码。
